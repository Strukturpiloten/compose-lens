# ComposeLens 0.1.8

ComposeLens 0.1.8 promotes service metadata labels through the source-aware document, effective
merged-project, and generated-document APIs. Existing parsing, processing, and rendering entry
points remain source-compatible.

## Added

- `Service::labels` with distinct mapping and sequence forms and source spans.
- `ProjectService::labels` with semantic-key merging, per-entry `EntrySyntax`, and complete key,
  value, and collection provenance.
- Explicit empty-string semantics for key-only service-label list entries, distinct from key-only
  environment-variable host resolution.
- `GeneratedLabel` and `GeneratedService::add_label` for deterministic ordered mapping output.
- Empty and embedded-equals values, duplicate-name rejection, parse-back validation, malformed-form
  recovery, and sensitive-value debug redaction.

## Compatibility

The public additions are source-compatible within the documented 0.1.x release line. Rust 1.85.0
remains the minimum supported Rust version. The private YAML dependency is not exposed.

## Semantic boundary

ComposeLens preserves label names accepted by authored Compose files and does not enforce Docker's
non-binding reverse-DNS naming recommendations. Docker Compose reserves its
`com.docker.compose.*` namespace at runtime; callers generating for an exact provider remain
responsible for compatibility policy. `label_file` stays outside this pure boundary because it
requires explicit file loading and precedence inputs.

## Upgrade guidance

Authored-input consumers can call `Service::labels` for one document or
`ProjectService::labels` after explicit loading, interpolation, merging, and optional profile
selection. Generators create `GeneratedLabel` values and add them to a `GeneratedService`; a
successful `ComposeDocumentBuilder::build` returns deterministic parse-back-validated YAML.

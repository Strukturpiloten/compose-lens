# ComposeLens 0.1.1

This patch release completes the consumer-discovered work needed for BoxFerry's loss-aware
multi-file Compose input. It hardens the YAML backend boundary, accepts a valid real-world scalar
that exposed the defect, and adds a native merged/profile-selected project view.

## Added

- `build_project_view` builds native effective Compose values directly from a `MergedProject` and
  optional matching `ProfileSelection`.
- `ProjectValue<T>` retains the merge operation, every contributing source span, the effective
  source, and sensitivity state for fields, collections, and collection items.
- `ProjectKey` retains all authored key locations. Merged environment entries retain their
  effective mapping, `KEY=VALUE`, or key-only list syntax.
- The first view boundary covers project name, services, images, commands, environment, ports,
  volume mounts, service networks, profiles, and top-level network, volume, config, and secret
  definitions.
- Fields outside that boundary remain visible as source-aware `ProjectFieldReference` values.
- Sensitive native project values redact their contents from `Debug` output.

## Fixed

- ComposeLens now accepts complete single-line block plain values containing commas, including
  unquoted short-volume options such as `./data:/data:Z,ro`.
- A constrained same-byte-length compatibility input is used only for the private YAML backend;
  public source text, scalar decoding, spans, editing, and preservation rendering remain based on
  the caller's original bytes.
- ComposeLens still compares the YAML document root with the complete caller-supplied source after
  a parse that otherwise reported no syntax errors.
- Input omitted from the document root emits the stable `compose.yaml.unparsed-input` error with a
  source span covering the omitted suffix.
- The original source and loss-aware concrete syntax tree remain available for inspection;
  preservation rendering stays byte-identical and typed processing cannot appear valid over a
  truncated root.

## Affected real-world form

The regression was triggered by an unquoted Compose short-volume scalar with comma-separated
options, for example `./data:/data:Z,ro`, followed by additional document content. The valid
unquoted spelling now parses, renders, merges, and reaches the typed short-volume model with both
`Z` and `ro` options intact. Quoting is no longer required as a workaround.

## Compatibility

The documented 0.1.x module paths and public processing stages remain source-compatible. The
`project` module is additive. The parser correction fixes behavior that contradicted the
loss-aware parse contract and does not normalize caller input. Rust 1.85.0 remains the minimum
supported Rust version.

## Upgrade guidance

BoxFerry and other adapters may continue consuming one `ComposeDocument`. Multi-file consumers
should migrate to `build_project_view` after explicit loading, optional interpolation, merge, and
profile selection. They should use `ProjectValue::provenance` rather than replacing original
locations through canonical render-and-reparse.

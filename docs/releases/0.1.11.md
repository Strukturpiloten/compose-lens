# ComposeLens 0.1.11

ComposeLens 0.1.11 promotes the service-level Compose `restart` field through every native library
layer needed by a converter.

## Added

- `Service::restart` and `RestartPolicy` for a source-aware authored scalar.
- `RestartPolicyKind` classifications for `no`, `always`, `on-failure[:max-retries]`,
  `unless-stopped`, deferred interpolation, and retained invalid/provider-specific values.
- `ProjectService::restart` for the effective multi-file policy with ordinary scalar-replacement
  provenance.
- `GeneratedRestartPolicy` and `GeneratedService::set_restart` for deterministic,
  parse-back-validated output.
- Stable document and project diagnostics for malformed forms and unknown policies without
  dropping the partial service or retained value.

## Semantics

ComposeLens retains the complete authored scalar. An optional decimal maximum-retry count is
classified but not numerically normalized, so `on-failure:003` remains exact. Interpolation is
deferred in the document model and interpreted only after the caller explicitly supplies and
applies an environment during project processing.

Service-level `restart` controls container behavior after termination. It is deliberately distinct
from `depends_on.<service>.restart`, which concerns explicit Compose-controlled dependency updates,
and from `deploy.restart_policy`. The supported policies follow the
[Docker Compose service reference](https://docs.docker.com/reference/compose-file/services/#restart).

Generated policies use a separate typed enum, quote the resulting scalar, reject duplicate setter
calls, and must parse back into the same native policy family. The public additions are
source-compatible within the documented 0.1.x policy. Rust 1.85.0 remains the minimum supported
version.

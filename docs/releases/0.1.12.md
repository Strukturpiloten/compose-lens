# ComposeLens 0.1.12

ComposeLens 0.1.12 promotes service-level Compose `env_file` declarations through the authored
document and effective merged-project boundaries needed by conversion adapters.

## Added

- `Service::environment_files` with distinct scalar/list short entries and mapping long entries.
- Source-aware long `path`, `required`, and `format` options, including deferred interpolation,
  retained extensions, retained unknown fields, and stable recoverable diagnostics.
- `ProjectService::environment_files` with Compose sequence-append order plus collection, item,
  and nested-field merge provenance.
- Sensitive interpolation propagation and redacted `Debug` output for environment-file paths and
  options.

## Semantics

ComposeLens describes declarations; it does not open, parse, or check the existence of an
environment file. Relative-path resolution remains an explicit application operation using the
origin associated with each contributing source. An absent long-form `required` means Compose's
default `true`; an explicit `false` remains distinct. An absent `format` means the default Compose
parser, while `format: raw` is classified without discarding the authored scalar.

Malformed items produce source-spanned diagnostics while other valid entries and useful partial
long entries remain available. The project view follows Compose's ordinary sequence append rule
instead of deduplicating paths.

Generated-document construction for `env_file` is not part of this release. The public additions
are source-compatible within the documented 0.1.x policy. Rust 1.85.0 remains the minimum
supported version.

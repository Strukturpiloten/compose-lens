# ComposeLens 0.1.6

ComposeLens 0.1.6 promotes service config and secret grants into the native merged-project
consumer view. Converters can now inspect their effective multi-file form without rendering and
reparsing YAML or reimplementing Compose's unique-resource merge rules.

## Added

- `ProjectService::configs` and `ProjectService::secrets` expose ordered effective grants with
  collection and per-item provenance.
- `ProjectGrant` preserves short resource-name syntax versus mapping-based long syntax.
- `ProjectLongGrant` exposes `source`, `target`, `uid`, `gid`, and `mode` with separate
  `ProjectValue` provenance and retains unknown or extension fields.
- Multi-file tests prove unique-by-target merging and nested values inherited from earlier files.
- Malformed mappings return source-spanned diagnostics and retain every representable grant.

## Compatibility

The public changes are additive within the documented 0.1.x compatibility line. Existing callers
do not need to change. Rust 1.85.0 remains the minimum supported Rust version.

## Semantic boundary

ComposeLens preserves effective Compose intent and provenance. It does not read config or secret
content, resolve environment-sourced resources, validate container ownership, or claim that
another runtime has an equivalent lifecycle. Those decisions belong to an explicit consumer or
target adapter.

## Upgrade guidance

Consumers using `build_project_view` can read grants directly from `ProjectService`. Inspect the
top-level `ProjectView::configs` and `ProjectView::secrets` definitions separately when deciding
resource ownership and lifecycle.

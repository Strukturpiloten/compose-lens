# ComposeLens 0.1.2

This patch release extends the native merged-project view with loss-aware Compose `extra_hosts`
entries. It prepares BoxFerry and other consumers to convert explicit host mappings without
reinterpreting the generic merged YAML tree.

## Added

- `ProjectService::extra_hosts` exposes effective host mappings after Compose field-aware merge and
  optional profile selection.
- `ProjectExtraHosts` retains effective merge order and collection provenance.
- `ProjectExtraHost` retains hostname key locations, address provenance, and whether its effective
  spelling came from sequence or mapping syntax.
- Addresses retain their authored spelling and distinguish IPv4, bracketed or unbracketed IPv6,
  the runtime token `host-gateway`, and other implementation-specific or deferred values.
- Public-contract and multi-file fixtures cover `host.docker.internal=host-gateway`, bracketed
  IPv6, mapping syntax, overrides, and per-entry provenance.

## Compatibility

The public changes are additive within the documented 0.1.x compatibility line. Existing callers
do not need to change. Rust 1.85.0 remains the minimum supported Rust version.

## Upgrade guidance

Consumers that already use `build_project_view` may read `ProjectService::extra_hosts` directly.
Do not infer or discard an explicit `host.docker.internal=host-gateway` mapping merely because a
particular runtime can synthesize a related hostname: runtime configuration and network behavior
can change whether such an implicit mapping exists.

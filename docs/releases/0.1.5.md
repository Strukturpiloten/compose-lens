# ComposeLens 0.1.5

ComposeLens 0.1.5 promotes execution identity and container context into the native
merged-project consumer view. Converters can inspect effective multi-file values without
rendering and reparsing YAML or resolving host runtime state.

## Added

- `ProjectService::user` exposes the raw container user and optional group with lexical component
  classification and complete merge provenance.
- `ProjectService::userns_mode` exposes the raw user-namespace mode and known-mode classification.
- `ProjectService::group_add` retains effective supplementary groups in Compose merge order, with
  provenance for the collection and every item.
- `ProjectService::working_dir` and `ProjectService::read_only` expose effective execution-context
  values with multi-file provenance.
- The single-document `Service` model now also types `group_add`, `working_dir`, and `read_only`.
- Malformed values produce recoverable, source-spanned diagnostics, and the supported public API
  test exercises all five fields.

## Compatibility

The public changes are additive within the documented 0.1.x compatibility line. Existing callers
do not need to change. Rust 1.85.0 remains the minimum supported Rust version.

## Semantic boundary

ComposeLens preserves authored intent. It does not resolve operating-system users or groups,
validate a working directory against an image, or inspect a provider's namespace state. Target
adapters remain responsible for version-aware support and for reporting exact, approximate,
unsupported, or invalid conversions.

## Upgrade guidance

Consumers using `build_project_view` can read these values directly. Use the outer and per-item
`ProjectValue` provenance when a conversion report must identify every contributing Compose file.

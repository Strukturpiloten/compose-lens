# ComposeLens 0.1.9

ComposeLens 0.1.9 corrects private YAML-backend behavior exposed by BoxFerry's pinned real-world
Compose corpus. No public type or processing-stage contract changes.

## Fixed

- Hyphenated anchor and alias names now retain their exact authored spelling while scalar,
  sequence, and mapping alias values reach typed loading and merging.
- A collision such as `shared-name` plus `shared_name` fails closed instead of resolving either
  name through an ambiguous compatibility spelling.
- Unquoted block-sequence items beginning with `--`, including comma-containing command options,
  remain independent scalars.
- One or more blank lines between a mapping key and its more-indented mapping value no longer make
  the key appear empty.
- Direct aliases are resolved only after structural indentation recovery, preventing fields from
  an anchored mapping from leaking into the alias consumer's parent mapping.

Every compatibility transformation is private and byte-length preserving. Public source text,
spans, preservation rendering, and scalar spelling continue to use the caller's original bytes.
Quoted and comment content is excluded from anchor-name handling, and the complete-root guard still
rejects any silently omitted input.

## Real-world evidence

The triggering pinned inputs are Apache Superset, Appwrite, and mailcow. Minimal authored
regressions live in ComposeLens so normal pull-request tests remain offline and independent of
upstream repositories.

## Compatibility

This patch is source-compatible within the documented 0.1.x release line. Rust 1.85.0 remains the
minimum supported Rust version, and the private YAML dependency remains outside the public API.

# ComposeLens 0.1.10

ComposeLens 0.1.10 promotes the Compose `container_name` field through every native library layer
needed by a converter.

## Added

- `Service::container_name` for the source-aware single-document scalar.
- `ProjectService::container_name` for the effective multi-file value and complete replacement
  provenance.
- `GeneratedService::set_container_name` for deterministic, parse-back-validated Compose output.
- `GenerationError::InvalidContainerName` for values outside the documented portable Compose
  grammar.

## Semantics

The service key and explicit runtime container name remain distinct. ComposeLens does not invent a
`container_name` when it is absent. Multi-file processing applies ordinary scalar replacement and
retains all contributing sources. Authored values remain exact scalar text; provider acceptance is
not inferred from successful parsing.

Generated names must match `[a-zA-Z0-9][a-zA-Z0-9_.-]+`. A second setter call is rejected rather
than overwriting the earlier choice. The public change is additive within the documented 0.1.x
policy and keeps Rust 1.85.0 as the minimum supported version.

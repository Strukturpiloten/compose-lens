# ComposeLens 0.1.3

ComposeLens 0.1.3 promotes service health checks into the native merged-project consumer view.
Converters and other consumers can now inspect the effective multi-file definition directly
without rendering and reparsing YAML or losing field-level provenance.

## Added

- `ProjectService::healthcheck` exposes the effective health-check mapping after Compose-aware
  merge and optional explicit profile selection.
- `ProjectHealthcheck` retains separate values and complete merge provenance for `test`,
  `interval`, `timeout`, `retries`, `start_period`, `start_interval`, and `disable`.
- Scalar and list command forms remain distinct, including `NONE`, `CMD`, and `CMD-SHELL`.
- `ProjectHealthcheck::is_disabled` recognizes both `disable: true` and `test: [NONE]`.
- Nested extension and unknown fields remain source-addressable through unmodeled field references.
- Malformed fields produce recoverable project-view diagnostics instead of panics or silent loss.

## Compatibility

The public changes are additive within the documented 0.1.x compatibility line. Existing callers
do not need to change. Rust 1.85.0 remains the minimum supported Rust version.

Compose `start_interval` remains a distinct source value. Consumers must not silently reinterpret
it as a runtime's separate startup-healthcheck mechanism when the operational semantics differ.

## Upgrade guidance

Consumers using `build_project_view` can read `ProjectService::healthcheck` directly. Use each
nested `ProjectValue` when diagnostics or conversion decisions need the exact source documents
that contributed to an effective field.

# ComposeLens 0.1.7

ComposeLens 0.1.7 adds deterministic construction of new Compose documents for converters and
runtime-migration tools. The existing authored-source, merge, canonical-render, and preservation
APIs remain unchanged.

## Added

- `ComposeDocumentBuilder` and Compose-owned generated value types in `compose_lens::render`.
- Generated images, commands, environment, execution context, host mappings, ports, mounts,
  service networks, and top-level network/volume lifecycle definitions with optional exact
  platform names.
- Deliberate short bind syntax for `GeneratedSelinux`, with ambiguous encodings rejected rather
  than silently losing relabel intent.
- Exact insertion-order rendering, duplicate-name and duplicate-field rejection, and deterministic
  golden bytes.
- Syntax and typed-model parse-back validation for every successful generated document.
- Sensitive generated strings and final-output debug redaction.

## Compatibility

The public additions are source-compatible within the documented 0.1.x release line. Rust 1.85.0
remains the minimum supported Rust version. The private YAML dependency is not exposed.

## Semantic boundary

Parse-back validation establishes valid ComposeLens syntax and native-model recovery. It does not
claim behavior parity across Docker Compose, `podman-compose`, Docker Engine, or Podman versions.
Compatibility profiles and runtime evidence remain separate explicit stages.

## Upgrade guidance

Converters that create new definitions should construct `GeneratedService` and related values,
add them to `ComposeDocumentBuilder`, and call `build` with a caller-owned `SourceId`. Read
deployable YAML through `GeneratedComposeDocument::text`; do not derive generated text from debug
output.
